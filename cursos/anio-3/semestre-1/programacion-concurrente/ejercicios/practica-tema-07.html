Nivel Máximo de Prioridad en Linux para SCHED_FIFO y SCHED_RR

Según la página 3 del Tema 7, aunque el estándar POSIX exige al menos 32 niveles de prioridad fija, en Linux el rango va desde 0 (para SCHED_OTHER) hasta un valor máximo para hebras de tiempo real. ¿Cuál es ese valor máximo entero?

Solución Razonada (Tema 7, Pág. 3)

En Linux el valor máximo de prioridad para SCHED_FIFO y SCHED_RR es 99.

Traza de la Función normalizar(struct timespec *tm)

Dada una estructura struct timespec tm con valores iniciales tm.tv_sec = 12 y tm.tv_nsec = 2450000000L (2,450,000,000 ns), calcula el valor final de tm.tv_sec tras invocar normalizar(&tm) (Tema 7, pág. 20):

Solución Razonada Paso a Paso (Tema 7, Pág. 20)
Como tv_nsec = 2,450,000,000 ≥ 1,000,000,000:
tv_sec += 2,450,000,000 / 1,000,000,000 = 12 + 2 = 14 s
tv_nsec = 2,450,000,000 % 1,000,000,000 = 450,000,000 ns

Ajuste de Tamaño a Frontera de Página en lock_memory(addr, size)

En la función lock_memory de la página 9 del Tema 7, se solicita bloquear un buffer de DATA_SIZE = 2048 bytes cuya dirección de inicio tiene un desplazamiento respecto al inicio de página de page_offset = 500 bytes. Tras ejecutar addr -= page_offset; size += page_offset;, ¿qué valor en bytes tiene el parámetro size que se pasa a mlock(addr, size)?

Solución Razonada Paso a Paso (Tema 7, Pág. 9)
size_final = size + page_offset = 2048 + 500 = 2548 bytes
