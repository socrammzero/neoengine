1. Problema de los Jardines y los Tres Intentos Fallidos de Espera Activa (Págs. 3–29)Espera Activa

En el Problema de los Jardines (págs. 4–15), dos puertas incrementan una variable global cont++ compilada en tres instrucciones máquina: load cont, inc 1, store cont. Si ambas hebras leen cont = 0 antes de almacenar, tras dos entradas el contador vale 1 en vez de 2.
Intento (Págs. 23–29) Preprotocolo / Postprotocolo ¿Cumple R1 (Exclusión Mutua)? Defecto Fatal (Contraejemplo de Traza)
Primer Intento (Págs. 23–25) f[miId]=1; while(f[otra]); / f[miId]=0; SÍ (Pi en SCi ⇒ f[i]==1) Viola R2 (Sufre Livelock): Si p0 hace f[0]=1 y p1 hace f[1]=1 simultáneamente, ambos quedan atrapados en el while.
Segundo Intento (Págs. 26–27) while(f[otra]); f[miId]=1; / f[miId]=0; NO (ERROR GRAVE) Viola R1 (Exclusión Mutua): Ambos evalúan f[otra]==0, ambos ponen f[i]=1 y entran juntos en la Sección Crítica.
Tercer Intento (Págs. 28–29) while(turno==otra); / turno=otra; SÍ (turno vale 0 o 1) Viola R3 (Alternancia Estricta): Si sólo p0 quiere entrar dos veces seguidas y p1 está en su SNC, p0 queda bloqueado porque turno==1.

2. Solución de Peterson (2 Procesos) y Panadería de Lamport (N Procesos) (Págs. 30–52)Algoritmos Canónicos

Peterson combina el array de intención unsigned f[2] = {0, 0}; del Intento 1 con la variable de desempate int turno = 0; del Intento 3: cada hebra declara su intención (f[miId] = 1;) y cede caballerosamente el turno a la otra (turno = otra;), esperando mientras while (f[otra] && turno == otra);. Satisface R1, R2, R3 y R4 (Justicia).

Algoritmo de la Panadería de Lamport para N ≥ 2 Procesos (Págs. 36–52)

Cada cliente id levanta la bandera pidiendoTurno[id] = 1, calcula su ticket turno[id] = siguiente() (el máximo actual más 1), baja pidiendoTurno[id] = 0 y luego comprueba contra cada cliente j: primero espera a que j termine de escoger ticket (while (pidiendoTurno[j]);) y después espera según el orden lexicográfico en while (!meToca(id, j));:

Orden Lexicográfico en meToca(id, i):   Pasa antes i que id  ⇔  (turno[i] > 0 ∧ turno[i] < turno[id]) ∨ (turno[i] == turno[id] ∧ i < id)

3. Propiedades de Seguridad, Viveza y Justicia del Planificador (Págs. 53–55)Verificación Formal

PROPIEDADES DE SEGURIDAD VS VIVEZA (Pág. 53)
  • Seguridad (Safety — "Nunca ocurre nada malo"): Exclusión mutua (R1), condiciones de sincronización del productor/consumidor y ausencia de deadlock.
  • Viveza (Liveness — "En algún momento ocurre algo bueno"): Ausencia de livelock (R2), progreso individual (R3) y ausencia de inanición o postergación indefinida (starvation, R4).
PLANIFICADOR DÉBIL VS FUERTEMENTE JUSTO (Pág. 55)
  • Débilmente justo: Si un proceso mantiene una petición de forma continua, en algún momento será atendida.
  • Fuertemente justo: Si una condición de petición se hace verdadera con infinita frecuencia (aunque se active y desactive en bucle como fin1=1; fin1=0;), en algún momento será atendida.

4. Semáforos POSIX (semaphore.h) y Productor/Consumidor Circular (Págs. 65–89)Tema 3_1

Un semáforo POSIX sem_t representa un número natural de permisos disponibles, manipulado atómicamente mediante sem_init(&s, 0, val), sem_wait(&s) (decrementa o suspende la hebra si vale 0) y sem_post(&s) (incrementa o despierta a una hebra bloqueada).
Regla Crítica de Orden en el Preprotocolo (Pág. 89) En el Productor/Consumidor es obligatorio esperar primero por el semáforo de condición (sem_wait(&Hay_espacio) o sem_wait(&Hay_Datos)) y después tomar la exclusión mutua (sem_wait(&mutex)). Si se invierte el orden (tomando primero mutex), el consumidor con el buffer vacío retiene mutex = 0 y se bloquea en Hay_Datos, provocando un interbloqueo (deadlock) total.
