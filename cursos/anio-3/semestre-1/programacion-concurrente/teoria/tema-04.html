Tema 4: Comunicación mediante Paso de Mensajes

Comunicación en sistemas débilmente acoplados sin memoria compartida: clasificación por direccionamiento y sincronización (asíncrona, cita síncrona y cita extendida), colas de mensajes POSIX (<mqueue.h>) e instrucción de espera selectiva (select con guardas when, terminate y else).

1. Clasificación de las Primitivas de Paso de Mensajes (Págs. 3–13)Taxonomía

Criterio Modalidad Sintaxis / Comportamiento Técnico
Identificación (Págs. 4–7) Directa Simétrica vs Asimétrica Simétrica: send(ms, pidB) / receive(ms, pidA). Asimétrica: send(ms, pidB) / receive(ms) (recibe de cualquiera).
Identificación (Págs. 4–7) Indirecta (Buzón / Canal) send(ms, canal) / receive(ms, canal). Topologías: 1:1 (unidireccional/bidireccional), 1:N, N:1 (cliente/servidor) y N:M.
Sincronización (Págs. 8–9) Comunicación Asíncrona El emisor no se bloquea (salvo cola llena); el receptor sólo se bloquea si el mensaje aún no está disponible en el canal.
Sincronización (Págs. 10–11) Síncrona (Cita / Rendezvous) Tanto emisor como receptor esperan a que el otro esté listo (handshake). No requiere buffer intermedio.
Sincronización (Págs. 12–13) Síncrona Extendida (Cita Extendida) El emisor espera a que el receptor reciba el mensaje y además espera bloqueado hasta recibir la respuesta send(ans, A).

2. Colas de Mensajes POSIX (<mqueue.h>) (Págs. 14–25)API POSIX

A diferencia de las tuberías (pipes) de UNIX, las colas de mensajes POSIX tienen estructura interna de registros, permiten asignar una prioridad entera a cada mensaje y consultar/controlar los atributos de la cola mediante struct mq_attr. Recuerda enlazar siempre con -lrt.
struct mq_attr { long mq_flags; long mq_maxmsg; long mq_msgsize; long mq_curmsgs; };
mqd_t mq_open(const char *name, int oflag, mode_t mode, struct mq_attr *attr);
int mq_send(mqd_t mqdes, const char *msg_ptr, size_t msg_len, unsigned int msg_prio);
ssize_t mq_receive(mqd_t mqdes, char *msg_ptr, size_t msg_len, unsigned int *msg_prio);
int mq_close(mqd_t mqdes);   |   int mq_unlink(const char *name);

3. Espera Selectiva: Sintaxis CSP/Ada y Función select() en Linux/C (Págs. 26–34)Select y Guardas

Si el proceso servidor IncVisitantes hace mq_receive(idcola, ...) seguido de mq_receive(idcola2, ...) (pág. 25), impone una alternancia rígida entre puertas. Para escuchar simultáneamente por cualquiera de los canales que tenga datos listos se emplea la espera selectiva:

Notación CSP (Pág. 26):   c!ms (envía ms por canal c)  |  c?v (recibe de canal c en variable v)
Rama con guarda (Pág. 31):   [when expBool =>] c?v;  → Abierta sii (expBool == true) ∧ (cita disponible en c)
Implementación en Linux/POSIX con Descriptores (Págs. 28–30 y 34) En Linux, un descriptor mqd_t es internamente un descriptor de fichero, lo que permite usar FD_ZERO(&rfds), FD_SET(cola[i], &rfds), select(maxfd + 1, &rfds, NULL, NULL, &tv) y comprobar qué cola tiene mensajes con FD_ISSET(cola[pos], &rfds). La rama else se simula pasando un struct timeval tv de timeout a select().
